# 需求文档：USD 多图预览体验极致优化

## 引言

USD 格式的数字资产（如 `house.usd`）通常包含多张渲染预览图（最多 11 张），这些图片从不同角度/光照条件展示 3D 资产。当前系统在三个关键场景下的用户体验存在明显缺陷：

1. **卡片区多图切换**：仅提供左右箭头逐张切换，对于 11 张图的资产操作效率低下
2. **右侧详情面板**：只展示单张图片（offset=0），无法浏览其他渲染图
3. **查找相似资产**：当 offset=0 的图片恰好是黑色/无效渲染图时，系统仍以该黑图作为相似搜索依据，导致 HTTP 500 错误和 0 结果

### 技术背景

- 后端通过 `/v3/images?url=<asset_url>&img_offset=<n>` 接口按 offset 返回不同渲染图
- `NavigableAssetImage` 组件通过 `loadProgressiveImages` 探测最大 offset
- `AssetDetailsDrawer` 使用 `AssetImage`（仅加载 offset=0）
- `handleFindSimilar` 传入 `baseKey`（资产路径），后端自动取 offset=0 的图片做向量搜索
- 部分渲染图为纯黑/近黑（渲染失败或特定角度），这些图片不适合作为相似搜索的输入

## 需求

### 需求 1：卡片区多图浏览体验升级

**用户故事：** 作为一名 3D 资产搜索用户，我希望能快速浏览一个 USD 资产的所有渲染图，以便高效评估资产质量而无需逐张点击箭头。

#### 验收标准

1. WHEN 用户 hover 到一个拥有多张预览图的资产卡片上 THEN 系统 SHALL 展示一种比纯箭头更高效的多图浏览方式（推荐方案见下方设计探索）
2. WHEN 资产只有 1 张预览图 THEN 系统 SHALL 不展示任何多图导航 UI，行为与当前一致
3. WHEN 用户使用新的多图浏览方式 THEN 系统 SHALL 保持图片切换流畅（< 100ms 感知延迟），利用已有的 progressive loading 缓存
4. IF 图片尚未加载完成 THEN 系统 SHALL 展示 shimmer skeleton 占位，不阻塞用户继续浏览其他图片
5. WHEN 用户离开卡片 hover 区域 THEN 系统 SHALL 保持当前浏览到的图片位置（不自动重置到第一张）

#### 设计方案探索（推荐方案 A）

| 方案                                   | 描述                                                                                                   | 优点                                                                  | 缺点                                 |
| -------------------------------------- | ------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------- | ------------------------------------ |
| **A. 底部圆点指示器 + hover 分区切换** | 卡片图片区域按图片数量等分为 N 个 hover 区域，鼠标水平移动即可切换图片；底部显示圆点指示器标记当前位置 | 零点击即可浏览全部图片；Fab.com / ArtStation 等主流资产平台的标准交互 | 需要精确计算 hover 区域              |
| B. 缩略图条                            | 图片下方展示一行小缩略图，点击切换                                                                     | 直观，可一眼看到所有图                                                | 占用卡片垂直空间；缩略图太小难以辨别 |
| C. 自动轮播                            | hover 时自动播放幻灯片                                                                                 | 无需任何操作                                                          | 用户无法控制节奏；可能错过想看的图   |

**推荐方案 A**：与 Fab.com、Sketchfab、ArtStation 等 3D 资产平台一致的交互范式，用户学习成本为零。

### 需求 2：右侧详情面板多图支持

**用户故事：** 作为一名 3D 资产搜索用户，我希望在右侧详情面板中能浏览资产的所有渲染图，以便在不离开搜索结果页的情况下全面了解资产外观。

#### 验收标准

1. WHEN 用户打开一个拥有多张预览图的资产详情面板 THEN 系统 SHALL 在预览区展示多图浏览能力（而非仅显示 offset=0 的单张图）
2. WHEN 详情面板展示多图 THEN 系统 SHALL 提供与卡片一致的交互方式（圆点指示器 + hover 分区 或 左右箭头 + 圆点指示器）
3. IF 某张预览图为纯黑/无效图 THEN 系统 SHALL 仍然展示该图（不跳过），但可在视觉上给予"可能无效"的提示（如半透明遮罩 + 图标）
4. WHEN 用户切换到不同资产 THEN 系统 SHALL 重置图片浏览位置到第一张有效图片（非黑图优先）
5. WHEN 详情面板首次打开 THEN 系统 SHALL 自动选择第一张"有效"预览图作为默认展示（跳过纯黑图），而非固定展示 offset=0

---

### 需求 3：查找相似资产 — 智能选图 + 黑图防护

**用户故事：** 作为一名 3D 资产搜索用户，我希望"查找相似资产"功能能自动使用最佳预览图（而非可能是黑色的 offset=0）作为搜索依据，以便获得有意义的相似搜索结果而非报错。

#### 验收标准

1. WHEN 用户点击"查找相似资产"按钮 THEN 系统 SHALL 使用当前卡片上正在展示的那张预览图（而非固定 offset=0）作为相似搜索的输入
2. IF 当前展示的图片被检测为"无效图"（纯黑/近黑） THEN 系统 SHALL 自动回退到第一张有效预览图，并通过 toast 提示用户"已自动选择最佳预览图进行搜索"
3. IF 资产的所有预览图均为无效图 THEN 系统 SHALL 禁用"查找相似资产"按钮，并通过 tooltip 说明原因（"该资产无有效预览图，无法进行相似搜索"）
4. WHEN 相似搜索因图片问题返回 HTTP 500 THEN 系统 SHALL 展示友好错误提示（"该预览图无法用于相似搜索，请尝试切换到其他预览图后重试"），而非通用的"Internal Server Error"
5. WHEN 用户在卡片上切换到某张预览图后点击"查找相似" THEN 系统 SHALL 在搜索结果顶部的"查找相似"标签中展示实际使用的那张预览图（而非黑图）

#### 黑图检测策略

检测一张图片是否为"无效/黑图"的方法：

- 将图片绘制到 canvas，采样像素平均亮度
- 阈值：平均亮度 < 10（0-255 范围）判定为"纯黑/无效"
- 该检测在图片加载完成后异步执行，不阻塞 UI

## 边界情况与约束

### 性能约束

- 多图 hover 切换必须利用 `loadProgressiveImages` 已缓存的图片数据，不产生额外网络请求
- 黑图检测必须异步执行，不阻塞首屏渲染
- 详情面板多图加载采用懒加载策略（仅加载当前展示 + 前后各 1 张）

### 兼容性约束

- 单图资产（offset=0 即为唯一图）的行为不得改变
- 非 USD 格式资产（.uasset / .fbx 等通常只有 1 张预览图）不受影响
- 所有改动必须遵守 `LM CUSTOMIZATION` 标记规范

### 国际化

- 所有新增文案必须同时加入 `i18n/en.js` 和 `i18n/zh.js`
- 涉及的新文案：黑图提示、自动选图 toast、按钮禁用 tooltip、错误提示优化

### 数据依赖

- `img_offset` 参数由后端 `/v3/images` 接口支持
- 后端 `vector_queries` 的 `query` 字段支持传入 `assetUrl` 或 `assetUrl?img_offset=N` 格式（需确认）
- 如果后端不支持带 offset 的相似搜索，需要改为前端先获取图片 base64 再传入 `query_type: "image"` + base64 数据
