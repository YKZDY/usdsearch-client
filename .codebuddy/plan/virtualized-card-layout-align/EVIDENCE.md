## 与上次修复(Task 5 EVIDENCE)偏差解释

之前的 [`.codebuddy/plan/click-and-layout-fixes/EVIDENCE-task5.md`](../click-and-layout-fixes/EVIDENCE-task5.md) 把 itemHeight 从 320 改回 360,理由是"非虚拟化分支自然撑开到 335px"。本轮重新实测发现:

1. **上轮测量维度不够**:只测了卡片矩形 outerHeight,没测**内部 6 个节点的 Y 坐标**;
2. **335px 数值不准**:本轮多次实测非虚拟化分支真实自然高度是 **317px**(可能上轮特定数据集 tag 偏多导致 335);
3. **flex={1} 撑开的副作用未识别**:itemHeight=360 比真实内容多 43px,被 `<VStack flex={1}>` 把这 43px 推到"大小行/按钮行"中间,形成"看似空白带 + 视口底部黑带"双重视觉问题。

本轮通过实测对比 BEFORE/AFTER 的 6 个内部节点 Y 坐标,精准证明 itemHeight=320 让虚拟化分支视觉与非虚拟化分支完全对齐(0px 差异)。

## 后续可选优化(不在本轮)

1. **gridSize='S' 进一步收敛**:188 → 172 可消除内部 16px 死带,但需复测 S 模式各种 tag 数量场景。
2. **itemHeight 配置抽取**:当前散落在 1257 行的硬编码数值,未来可抽到 `constants/grid.js` 集中管理。
3. **非虚拟化分支自然高度回归保护**:如果未来非虚拟化分支布局变化(如多一行内容),itemHeight 需对应调整 — 可通过 ResizeObserver 自动测量提供保护。

## 第二轮修复(2026-05-25 二次精准实测)

### 用户反馈

第一轮 itemHeight=320 修复后,用户实测反馈:

1. **卡片底部按钮被挤压**(图1红框 — 复制/查找按钮紧贴大小行,无呼吸空间)
2. **视口底部仍有大段黑色**

### 真因再调查

第一轮我用错了测量方法:**抓到的是 `chakra-stack` 内容区(317px)而非 `chakra-card` 整张卡(335px)**,导致 itemHeight 设小了 15px,把卡片内容**强行挤压**。

精准用 `.chakra-card` 选择器实测:

| 维度                                                                        | 真实值                         |
| --------------------------------------------------------------------------- | ------------------------------ |
| `chakra-card` 高度                                                          | **335px** ⭐(含 padding)       |
| `chakra-card__body` 高度                                                    | 333px                          |
| 内部 `chakra-stack` 高度                                                    | 317px(纯内容,不含卡片 padding) |
| 水平 gap                                                                    | 16                             |
| 垂直 gap                                                                    | 16                             |
| react-window `rowHeight = itemHeight + gap` 公式(VirtualizedResults.jsx:77) | 确认 itemHeight 不含 gap       |

⇒ **正确 itemHeight = 335**(贴 chakra-card 自然高度)

### 第二轮修复

`itemHeight=320 → 335`

### 教训

- 之前误用了 `cursor=pointer` + `copy按钮祖先` 抓父级,实际抓到的是中间层(chakra-stack),**比卡片真实根 chakra-card 少了一层 padding**
- 应直接用 **DOM 类名 `.chakra-card`** 抓最准
- 实测要观察"内容是否溢出 itemHeight"作为关键指标 — 这次 chakra-card\_\_body.bottom = 334 > cardHeight 320 是明显的溢出信号
