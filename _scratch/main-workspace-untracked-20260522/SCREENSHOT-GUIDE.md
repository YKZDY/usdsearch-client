> **配套**：本规范用于填写 [SOP-WECOM-SHEET.csv](./SOP-WECOM-SHEET.csv) 中的「预期效果截图」「实际截图」两列。
> **目标**：让任何人不看测试细节，只看截图就能判断该用例是否通过。

---

## 一、什么时候必须截图

| 场景               | 是否必须截图            | 截图数量                      |
| ------------------ | ----------------------- | ----------------------------- |
| P0 用例 - 预期效果 | ✅ 必须                 | 1~3 张                        |
| P0 用例 - 实际通过 | ⭕ 建议（首次回归必须） | 1 张                          |
| P0 用例 - 实际失败 | ✅ 必须                 | 2~5 张（现场+控制台+Network） |
| P1 用例 - 预期效果 | ⭕ 建议                 | 0~1 张                        |
| P1 用例 - 实际失败 | ✅ 必须                 | 1~3 张                        |
| REGR 历史翻车      | ✅ 必须                 | 至少 1 张明显证据             |
| 控制台报错相关     | ✅ 必须                 | 控制台 + Network 各 1 张      |

**原则**：宁可多截，不可漏截。截图丢失 = 该条 SOP 视为未测。

---

## 二、3 类必备截图

每条 P0 用例的「预期效果」字段都应包含以下 3 类中的**至少 1 类**，复杂用例 2~3 类全配：

### 类型 A · 状态截图（UI 呈现）

**适用**：验证视觉/交互结果（如选中态、高亮、过滤后列表、弹窗）
**示例**：

- 分类侧边栏「建筑」高亮为金色 #FFD230
- 多选模式下 SelectionModeBar 出现在底部
- 卡片左上角 Checkbox 选中态

### 类型 B · 数据截图（DevTools 证据）

**适用**：验证后端调用、参数、连接（普通用户看不见的部分）
**示例**：

- Network → `/search_hybrid` 请求的 Payload 含 `filter_by_tags: ["建筑"]`
- Console → 无红色 Error
- Network → `wss://...` 连接 status = 101 Switching Protocols
- Application → localStorage 中 token 存在

### 类型 C · 对照截图（Before / After）

**适用**：验证状态切换、增删改动作
**示例**：

- 操作前的卡片样式 vs 操作后的选中样式（拼图）
- 添加 tag 前 vs 添加后的标签列表
- 切换服务器前后的结果差异

## 三、截图命名规范（强制）

格式：

```
<编号>-<序号>-<简述>.png
```

**示例**：

```
M2-P0-03-①-分类高亮态.png
M2-P0-03-②-Network-Payload-含tag.png
M2-P0-03-③-结果列表全含建筑tag.png
M5-P0-07-①-添加tag前.png
M5-P0-07-②-添加tag后.png
M8-P0-04-①-控制台wss连接101.png
```

**规则**：

1. **编号**：必须与 CSV 第一列「编号」完全一致（如 `M2-P0-03`）
2. **序号**：用 `①②③④⑤` 圆圈数字，对应「预期结果」字段里的同序号要点
3. **简述**：4~10 个汉字，能让别人不看图就大致知道内容
4. **格式**：优先 PNG（无损），文件大于 1MB 时压缩为 JPG（质量 80）
5. **失败截图**：在简述前加 `FAIL-`，如 `M2-P0-03-FAIL-①-tag未传.png`

## 四、标注要求

### 4.1 必须标注的元素

- 🟥 **红框**：圈出本张图的关键观察点（不超过 3 处）
- 🔢 **序号**：与命名里的 `①②③` 对应，让 reviewer 一眼定位
- 💬 **关键文字**（可选）：贴一句话解释（如「应为金色 #FFD230」）

### 4.2 标注样式建议

| 元素             | 颜色                  | 粗细      |
| ---------------- | --------------------- | --------- |
| 红框（关键证据） | `#FF3B30`             | 3px       |
| 序号圆圈         | `#FF3B30` 填充 + 白字 | 直径 24px |
| 文字注释         | 黑底白字 / 黄底黑字   | 14~16px   |
| 失败现场红叉     | `#FF3B30`             | 8px 粗线  |

### 4.3 不要做的事

- ❌ 不要全图标满红框（重点不突出）
- ❌ 不要在浏览器内置 DevTools 上叠 PS 重影
- ❌ 不要遮住关键 URL / 时间戳（验真需要）
- ❌ 不要使用花哨的箭头/贴纸（专业感差）

## 五、推荐工具

### Windows（推荐 Snipaste）

| 工具                   | 截图        | 标注                  | 贴图             | 推荐度     |
| ---------------------- | ----------- | --------------------- | ---------------- | ---------- |
| **Snipaste**           | F1          | ✅ 内置画框/文字/序号 | ✅ F3 贴桌面对照 | ⭐⭐⭐⭐⭐ |
| **ShareX**             | Ctrl+PrtSc  | ✅ 强大               | ✅               | ⭐⭐⭐⭐   |
| **Win+Shift+S** + 画图 | 系统自带    | 一般                  | ❌               | ⭐⭐⭐     |
| **Snip & Sketch**      | Win+Shift+S | 弱                    | ❌               | ⭐⭐       |

**Snipaste 三键流**（强烈推荐熟练这一套）：

1. `F1` → 框选区域 → 用工具栏画红框 + 加序号 → `Ctrl+S` 直接命名保存
2. `F3` → 把刚才的图贴到桌面，方便和实际效果做 **左右对比**
3. 复杂场景：`F1` 截两张 → 用 PS / 系统画图横向拼接为对照图

### macOS

- 系统截图 `Cmd+Shift+4` + 预览 App 标注
- **CleanShot X**（付费但好用）

### 浏览器全屏长截图

- Chrome DevTools：`Ctrl+Shift+P` → `Capture full size screenshot`
- 用于结果列表很长需要完整呈现的场景

## 六、敏感信息打码

涉及以下内容**必须打码**（用纯色矩形覆盖，不要用模糊滤镜，能被还原）：

- 用户名 / 邮箱 / 手机号
- 内网 IP、内网域名（如 `xx.tencent.com` 中段）
- Token / Cookie / Authorization header（DevTools Network 截图常见）
- localStorage 里的 token 字段
- 真实客户/项目名

**打码工具**：Snipaste 的「矩形」工具填充黑色即可。

## 七、企微表格中的图片操作

### 上传方式

1. **拖拽**（推荐）：从文件夹直接拖进单元格
2. **粘贴**：截图后直接 `Ctrl+V` 到单元格
3. **批量上传**：右键单元格 → 上传图片 → 多选

### 多图组织

- 一个单元格支持多张图片
- 图片在单元格内自动横向排列，点击放大
- **顺序很重要**：按命名里的 `①②③` 顺序上传，企微会保留上传顺序

### 图片预览

- 单击：放大查看
- 双击：进入幻灯片模式（多图时可左右翻页）
- 右键：下载原图

## 八、最低标准检查清单

提交一条 SOP 截图前，自检以下 5 点：

- [ ] 文件名符合 `<编号>-<序号>-<简述>.png` 格式
- [ ] 序号与「预期结果」字段里的 ①②③ 对应得上
- [ ] 关键观察点用红框圈出，最多 3 处
- [ ] 敏感信息已打码
- [ ] 在企微表格里点开能看清，不模糊不变形

## 九、常见反例

### ❌ 反例 1：截图无标注，让人猜

模糊的全屏截图，分类侧边栏夹在 100 个元素里，reviewer 不知道看哪。

✅ **正确**：用红框圈出「建筑」分类项，加 ① 标注「应为金色 #FFD230」。

### ❌ 反例 2：失败只截一张 UI 图

"标签添加失败"只给一张 UI 截图，看不到原因。

✅ **正确**：截 3 张：①UI 现场（标签没出现） + ②Console 红色 Error + ③Network wss 连接状态。

### ❌ 反例 3：命名混乱

`截图1.png` `Snipaste_2026-05-14_18-32-12.png` 直接拖进表格。

✅ **正确**：`M5-P0-07-①-添加tag后.png`，让人一看就知道属于哪条 SOP 的哪个证据点。

### ❌ 反例 4：暴露 token

DevTools Headers 截图直接放上 `Authorization: Bearer eyJhbGc...`。

✅ **正确**：用黑色矩形覆盖 token 主体，只露开头 `eyJhbGc...***`。
