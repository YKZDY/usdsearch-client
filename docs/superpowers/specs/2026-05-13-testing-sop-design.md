# 测试 SOP 设计文档

**日期**: 2026-05-13  
**状态**: 已确认  
**目标**: 为 usdsearch-client 前端项目创建一套全面的手动测试 SOP

---

## 背景

- 前端由一人开发+测试，之前排期紧全部用来赶需求
- 几乎无测试 SOP，每次仅"点一下新功能没问题就下一个"
- 导致频繁出现：影响范围不明、边界漏测、状态交叉 bug、回归不足
- 该版本需给和平精英团队演示，不能翻车
- 需要一套可执行的 Markdown Checklist，照着过就能保证覆盖

## 设计决策

### 方案选择：按功能模块分区（方案 A）

- 将前端功能划分为 12 个独立测试模块
- 每个 checklist 项标注 [P0]（核心路径）或 [P1]（边界/异常）
- 快速验收 = 只跑 [P0]，完整回归 = 全量
- 模块间依赖关系明确标注，修改某模块后知道连带要测哪些

### 交付物

```
docs/testing-sop/
├── DEMO-SMOKE.md           # 演示前 Smoke Test（~15min）
├── QUICK-CHECK.md          # 日常快速验收（P0 only，~30min）
├── FULL-REGRESSION.md      # 完整回归（全量，~2h）
├── DEPLOY-CHECK.md         # 部署后专项检查（~20min）
├── MODULE-DEPENDENCY.md    # 模块依赖图 + 快查表
├── KNOWN-PITFALLS.md       # 历史翻车点记录
└── CHANGELOG.md            # SOP 变更记录
```

### 使用场景映射

| 场景 | 使用文件 | 耗时 |
|------|---------|------|
| 演示前 | DEMO-SMOKE.md | 15 min |
| 开发完一个 feat/fix | QUICK-CHECK.md（相关模块） | 10-30 min |
| 发版前 | FULL-REGRESSION.md | ~2h |
| 部署到生产后 | DEPLOY-CHECK.md | 20 min |
| 定期巡检（每 2 周） | FULL-REGRESSION + 重点交叉联动 | ~2h |
| 踩坑后 | 更新 KNOWN-PITFALLS.md | - |

## 模块划分

12 个测试模块：搜索核心、过滤器、结果展示、图片加载、资产详情、标签系统、目录树、认证&服务器、多选交互、演示专项、i18n 视觉、部署差异。

详细依赖关系见 `MODULE-DEPENDENCY.md`。

## 特殊设计点

1. **演示专项 (DEMO-SMOKE)** — 15 分钟 smoke test，只覆盖演示路径的最小集
2. **部署差异检查 (DEPLOY-CHECK)** — 针对"本地正常线上坏"的历史问题
3. **历史翻车回归 [REGR]** — 所有历史踩坑点的定向验证，发版必过
4. **状态交叉联动** — 专门覆盖跨模块的状态相互影响场景

## 执行规则

- 日常验收：跑改动模块 [P0] + 查依赖表连带相关模块 [P0]
- 发版回归：FULL-REGRESSION 全量，[P0] + [P1] + [REGR] 全部必过
- 定期巡检（每 2 周）：等同发版回归
- 通过标准：[P0] 全过才能发版；[P1] 允许已知问题但需记录；[REGR] 全过（不允许回退）
